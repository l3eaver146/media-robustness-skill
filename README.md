# Media Robustness Skill

Зафиксированная версия **1.0.0** обработки видео и картинок для локальных экспериментов с системами анализа медиа. Один Codex-скилл, несколько именованных профилей, пакетная обработка и отчёты проверки. Код не обращается к внешним моделям и не загружает медиа в сеть.

| Профиль | Назначение |
|---|---|
| `production` | Прежний боевой `adaptive_smooth`; профиль по умолчанию |
| `hard` | Видео: V06 с деформацией, сеткой и краткими заменами кадров. Картинки: максимальный статический DCT/pHash-профиль |
| `multiscale` | V05 с нормировкой смеси сеток |
| `protected` | Ослабление обработки на контурах и необязательные защищённые прямоугольники |
| `stable` | Стабилизация цвета нижнего текста во времени |
| `encode-only` | Контрольное перекодирование без численного преобразования пикселей |

Названия не означают доказанную эффективность против неизвестной системы. Изменение хеша не равнозначно ошибке понимания сцены; незаметность человеку не гарантируется. В `hard` для видео есть видимые при остановке карточки. Их можно отключить через `--no-context`.

## Установка скилла

Склонируйте репозиторий и скопируйте `skills/media-robustness` в каталог своих Codex-скиллов (`~/.codex/skills/` по умолчанию). После обновления списка скиллов он доступен как `$media-robustness`.

```bash
git clone --branch v1.0.0 https://github.com/l3eaver146/media-robustness-skill.git
mkdir -p ~/.codex/skills
cp -R media-robustness-skill/skills/media-robustness ~/.codex/skills/
```

При существующей установленной версии сначала сравните её с новым снимком; команда выше предназначена для первой установки. Для дальнейшей разработки используйте `main`, а для воспроизводимого запуска — тег `v1.0.0`.

## Запуск без Codex

Нужны Python, FFmpeg/ffprobe и системный шрифт. Создайте отдельное окружение:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r skills/media-robustness/requirements.txt
.venv/bin/python skills/media-robustness/scripts/process_media.py \
  --input "/путь/к/оригиналам" --output "/путь/к/новому_результату" \
  --profiles production hard --jobs 2
```

Вход может быть файлом или папкой с вложенными папками. `--top-level` ограничивает обработку корнем, `--kind image` / `--kind video` — типом медиа. Выходная папка должна быть новой и находиться вне исходной. Исходники не перезаписываются.

Готовые файлы: `images/<профиль>/` и `videos/<профиль>/`, с сохранением вложенной структуры. Отчёты и журналы: `_reports/`. При завершении проверьте `status.json` и хеши; успешное кодирование не означает успешного воздействия на модель.

Поддерживается портретное видео 8-bit SDR/CFR и непрозрачные RGB JPEG/PNG. Максимальный профиль картинок в этом снимке рассчитан на 1080×1920. Детали форматов, проверок, звука, EXIF/ICC и шрифтов — в [runtime.md](skills/media-robustness/references/runtime.md), параметры и происхождение — в [profiles.md](skills/media-robustness/references/profiles.md).

## Разработка и фиксация

```bash
python3 -m unittest discover -s tests -v
```

Тесты используют синтетические данные. В репозитории нет пользовательских видео, картинок, локальных журналов, ключей и шрифтов. Перед новыми релизами сохраняйте совместимость профилей либо явно меняйте версию/название; сравнивайте параметры, пиксельный результат, конечное кодирование и реальные результаты анализатора отдельно.

Проверка снимка 1.0.0: **34 теста прошли**, включая запуск всех шести профилей на изображении и видео со звуком. Перенесённые численные преобразования совпали с прежними скриптами на 40 синтетических видеокадрах и трёх статических примерах. Проверено на macOS ARM64, Python 3.14.2 и FFmpeg 9.0.1; шрифт Arial. Это проверка сохранения реализации и файлов, а не эффективности против анализатора.

В этом первоначальном снимке лицензия на распространение и производные работы отдельно не выбрана.
